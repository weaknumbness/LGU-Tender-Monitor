# Монитор закупок ЛГУ
Браузерная версия на React, TypeScript и Vite. Все вычисления выполняются на компьютере пользователя. RSS и HTML-страницы загружаются вручную. Здесь нет серверных API, ИИ, установщика или общей базы. Профили, заметки и рабочие статусы хранятся в IndexedDB браузера. При очистке данных сайта они удалятся. На новом ПК или в другом браузере будет отдельная база.

## Опубликовать без Node.js
1. Распакуйте архив. Создайте репозиторий GitHub.
2. Загрузите **содержимое** папки LGU-Tender-Monitor в корень ветки main. На главной странице репозитория должны быть видны src, docs и package.json. Сам ZIP загружать не нужно.
3. В Settings → Pages → Build and deployment выберите Deploy from a branch, затем main и /docs → Save.
4. Дождитесь публикации и откройте адрес из Settings → Pages.
5. Для проверки вручную выберите examples/demo.xml в поле импорта. В каждой из трёх групп должна появиться одна учебная запись. Для работы выберите сохранённые HTML-страницы или RSS из ЕИС. Повторный импорт обновляет закупки с тем же номером и сохраняет заметки и статусы.

## Как читать проект
1. index.html содержит узел root, а src/main.tsx вставляет туда React-приложение.
2. src/App.tsx связывает вкладки, поиск, выбор файла и сохранение. Найдите функцию upload и проследите путь файла.
3. src/lib/importFile.ts читает выбранный файл, определяет кодировку и объединяет данные по идентификаторам.
4. src/lib/integration-core.ts извлекает название, заказчика, цену и ссылку из RSS ЕИС и объединяет новую запись с сохранённой.
5. src/lib/procurement.ts описывает типы Tender и Profile, стартовые профили 12 подразделений и рабочие статусы.
6. src/lib/screening.ts сравнивает название и описание закупки с профилями. Совпадение в названии весит больше; для поставок товаров и широких формулировок действуют отдельные правила. Функция screen возвращает группу, причину и найденные фразы.
7. src/App.tsx содержит карточку закупки, панель рассмотрения и форму решения. Группа отбора вычисляется автоматически, а рабочий статус выбираете вы.
8. Вкладка профилей в src/App.tsx позволяет создавать подразделения и менять ключевые слова; src/components/Controls.tsx содержит вкладки и диалоги. Изменения относятся к текущему браузеру. Чтобы изменить стартовый словарь для новых пользователей, отредактируйте procurement.ts.
9. src/lib/storage.ts читает и записывает рабочую область в IndexedDB. src/index.css задаёт общие стили, src/App.css — оформление интерфейса.
10. public/ — файлы, которые Vite копирует без обработки; docs/ — готовый сайт для публикации; tests/ — примеры проверок алгоритма и разбора RSS.

## Разработка на личном компьютере
Для редактирования достаточно любого текстового редактора. Для запуска режима разработки и пересборки используйте Node.js 24 и npm:
```sh
npm ci
npm run dev
```
Откройте адрес из терминала. Проверка и выпуск изменений:
```sh
npm test
npm run build
```
После изменения src загрузите в GitHub и исходники, и обновлённую папку docs. Простое изменение src не меняет уже собранный сайт. Не редактируйте сжатые файлы docs/assets вручную. node_modules создаётся командой npm ci по package-lock.json; для GitHub Pages она не нужна. Конфигурация vite.config.ts задаёт относительные пути, поэтому сайт работает по адресу с названием репозитория.

## Границы разбора
Это предварительный отбор. Он проверяет текст из импортированных файлов, не скачивает документацию конкурса и не подтверждает право участвовать. Если данных нет, соответствующее поле останется пустым. Пример RSS содержит вымышленные номера и не предназначен для перехода к реальным извещениям.

## Профили и исключения
Профили подразделений → Добавить профиль. Введите название и ключевые слова через точку с запятой. Профиль сразу участвует в отборе. Источники и настройки → Чёрный список: запишите слова или фразы, сохраните список. Если в названии есть полное слово или последовательность слов, результат всегда «Не подходит · чёрный список» в группе «Совпадений нет». Регистр и различие е/ё не важны, формы слов нужно указывать отдельно. Закупка, заметки и ручной рабочий статус сохраняются. Удаление правила возвращает обычную классификацию. Профили и исключения локальны для этого браузера.

## Как загрузить несколько страниц поиска ЕИС

Откройте первую страницу результатов, дождитесь карточек, нажмите Ctrl+S и сохраните как HTML под именем page-1.html. Повторите на каждой нужной странице с новым именем. Папки с изображениями не нужны. В приложении нажмите «Импорт RSS и HTML» → «Выбрать файлы» и выделите все страницы. Можно одновременно добавить RSS. Итог показывает число новых, повторных и нераспознанных записей. После импорта открывается подборка с совпадениями; остальные записи доступны через фильтры.

Разбор HTML находится в src/lib/importHtml.ts; src/lib/importFile.ts определяет формат по содержимому и объединяет записи по идентификатору ЕИС.
